# Бот-копилка Telegram

Пересылаешь боту сообщение или файл из любого личного диалога (юрист,
сторител, блогеры) — оно попадает на вкладку **«Telegram»** страницы
**«Почта»** в админке: текст, файл в хранилище, короткая выжимка и факты,
вытащенные моделью. Разбирает человек — автозаписи в карточки нет.

Владелец, 2026-09-16: «я общаюсь там и со сторителем, и с юристом, по идее
система могла бы из диалогов получать много инфы + вложения… Давай делать
бот-копилку».

## Почему копилка, а не подключение личного аккаунта

Официальный способ вести личную переписку из CRM существует — **Telegram
Business**: на аккаунт с Premium вешается свой бот, он видит сообщения в
личных чатах (включая те, что владелец пишет сам с телефона) и отвечает от
имени владельца через `business_connection_id`. Не выбран сейчас по трём
причинам: живых диалогов восемь, и лента чата в CRM была бы пустой страницей;
нужен Premium; бот получает доступ к личным чатам целиком, то есть в базу
потечёт и непроработающая переписка. Пересылка вручную фильтрует на входе —
в системе оказывается только то, что владелец сам счёл важным.

Признаки, по которым пора переходить на Business (любого одного достаточно):
пересылать надоело и поток прекратился; диалоги должен вести кто-то кроме
владельца; диалогов стало десятки.

Отдельной serverless-функции у вебхука нет намеренно: в `api/` ровно 12
функций — потолок Vercel Hobby, тринадцатая роняет деплой целиком.

## Настройка (один раз)

1. **Создать бота.** В Telegram написать `@BotFather` → `/newbot` → имя и
   юзернейм (например `redevelopment_capture_bot`). В ответ придёт токен вида
   `8123456789:AAF...` — это пароль от бота, его нельзя публиковать.
2. **Положить секреты в Vercel** (Settings → Environment Variables, все три
   на Production):
   - `TELEGRAM_BOT_TOKEN` — токен из шага 1;
   - `TELEGRAM_WEBHOOK_SECRET` — любая случайная строка (например, вывод
     `openssl rand -hex 16`), ею подписываются входящие апдейты;
   - `TELEGRAM_ALLOWED_USER_IDS` — id тех, кого бот слушает, через запятую.
     Свой id пока неизвестен — оставить пустым, см. шаг 4.
3. **Зарегистрировать вебхук** (после деплоя с новыми переменными):

   ```bash
   curl -sS "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
     -H "Content-Type: application/json" \
     -d '{"url":"https://redevelopment.pro/api/telegram-webhook",
          "secret_token":"<TELEGRAM_WEBHOOK_SECRET>",
          "allowed_updates":["message"]}'
   ```

   Проверка: `curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"` —
   должно быть `"url": "https://redevelopment.pro/api/telegram-webhook"` и
   пустое `last_error_message`.
4. **Узнать свой id.** Написать боту что угодно: пока
   `TELEGRAM_ALLOWED_USER_IDS` пуста, он ничего не пишет в базу, а отвечает
   «Ваш Telegram id: …». Это число (или несколько через запятую) вписать в
   переменную и передеплоить.
5. **Проверить.** Переслать боту любое сообщение с файлом — в ответ придёт
   «Записал в копилку» с выжимкой, запись появится на вкладке «Telegram».
6. Подставить юзернейм бота в `TELEGRAM_CAPTURE_BOT`
   (`src/data/telegramCaptures.ts`) — он показывается в подсказке на пустой
   ленте. Пока пусто, подсказка просто без имени.

## Что бот умеет и чего не умеет

- Берёт текст, подпись к файлу и одно вложение: документ, фото, видео,
  аудио, голосовое. Файл до 20 МБ — потолок самого Bot API на скачивание
  ботом, больше он физически не получит и честно об этом пишет в ответ.
- Альбом из нескольких фото Telegram шлёт отдельными сообщениями — в копилке
  это будет несколько записей.
- Имя исходного автора у пересланного сообщения может отсутствовать: если у
  собеседника закрыта ссылка при пересылке, Telegram отдаёт только имя, а
  иногда и вовсе ничего. В ленте это «Отправитель скрыт», подпись правится
  руками.
- Посторонних бот игнорирует молча (не отвечает вовсе) — чтобы случайный
  человек не понял, что попал в рабочий инструмент.
- Разбор моделью (Haiku через ProxyAPI) не обязателен: если модель
  недоступна, сообщение всё равно сохраняется, просто без выжимки.
