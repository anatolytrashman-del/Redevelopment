# Связка Claude ↔ Codex (ChatGPT Pro)

Заведено 2026-09-17, когда недельный лимит Claude просел до 13%, а владелец купил
подписку ChatGPT Pro. Цель — переложить на Codex ту часть работы, которая не требует
живых секретов и живой базы, и тратить лимит Claude только на постановку задач,
миграции, деплой и приёмку.

Правила для самого Codex лежат в `AGENTS.md` в корне — он читает их автоматически.
Этот файл про то, КТО что делает и КАК задача доезжает от Claude до Codex.

## Что важно знать про тарифы

Подписка **ChatGPT Pro не включает API-доступ**: `platform.openai.com` тарифицируется
отдельно, по токенам. Зато Pro включает **Codex** — он же ходит под аккаунтом ChatGPT
и ест лимит подписки, а не отдельный счёт. Поэтому связка строится на Codex, а не на
OpenAI API. Заводить `OPENAI_API_KEY` имеет смысл, только если понадобится вызывать
модель из кода прода (сейчас такой нужды нет — там ProxyAPI и Claude).

## Три канала, по убыванию автономности

### 1. `codex` CLI прямо в сессии Claude (полная автоматика)

Claude зовёт Codex из Bash как субагента и сам принимает результат. Требует:

- в Allowed domains окружения: `chatgpt.com`, `auth.openai.com`, `api.openai.com`
  (первый — основной, через него Codex CLI ходит в бэкенд под аккаунтом ChatGPT);
- переменную окружения `CODEX_AUTH_JSON` — содержимое `~/.codex/auth.json` с машины,
  где владелец один раз выполнил `codex login` («Sign in with ChatGPT»).
  Это учётные данные аккаунта ChatGPT: не печатать в чат и в логи, не коммитить.
  Переменная окружения сессии подхватывается только СЛЕДУЮЩЕЙ сессией, не текущей.

Дальше работает обёртка `scripts/codex.sh` — она восстанавливает `auth.json`, при
необходимости ставит CLI и запускает задачу:

```bash
scripts/codex.sh "Перепиши фильтр поставщиков в src/pages/Suppliers.tsx на ..."
```

### 2. Codex Cloud + GitHub (без доступа из контейнера)

Владелец на chatgpt.com/codex подключает репозиторий `anatolytrashman-del/Redevelopment`,
базовой веткой ставит `claude/redevelopment-platform-prototype-oodobu`. Claude кладёт
задачу в очередь ниже, владелец запускает её в Codex одной кнопкой, Codex открывает PR.
Ничего открывать в окружении не нужно — канал работает всегда, это запасной путь.

### 3. Обычный чат ChatGPT

Для разовых вопросов без правки кода: разбор чужого API, текст письма, ресёрч рынка.
Результат владелец приносит в диалог.

## Кто что делает

**Codex забирает:** изолированные правки фронта по готовому ТЗ, рефакторинг,
вёрстку и адаптив, тесты (vitest), типизацию, разбор и чистку мёртвого кода,
генераторы в `scripts/`, текстовый SEO-контент, подготовку SQL-файлов миграций.

**За Claude остаётся:** всё, где нужны секреты и живые сервисы — применение миграций
через Supabase Management API, разовые прогоны по живой базе, разбор почты Resend,
Edge Functions в Supabase, наблюдение за деплоем Vercel, мерж PR, журнал сессий,
приёмка работы Codex.

**Пограничное — решает Claude:** если задача требует знать поведение живых данных
(сколько там строк, какие значения реально встречаются), Codex сделает вслепую и
ошибётся. Такие задачи либо остаются у Claude, либо Claude сначала снимает срез
данных и кладёт цифры прямо в ТЗ.

## Формат ТЗ для Codex

Codex не видел этот диалог и стартует с чистого листа. В задаче обязаны быть:

1. **Цель** одним абзацем — что должно получиться с точки зрения пользователя.
2. **Файлы** по путям от корня репозитория — где смотреть и что править.
3. **Ограничения** — что трогать нельзя, какие правила из `AGENTS.md` тут критичны.
4. **Критерий готовности** — «чистый `npm run build:app`» плюс что должно измениться
   на экране или в данных.
5. **Контекст из живой базы**, если он нужен, — цифрами, а не отсылкой «посмотри в БД».

## Приёмка

PR от Codex Claude смотрит как чужой код: диф целиком, сборка, соответствие
`AGENTS.md` (особенно `.range()` на выборках, `value || null` на датах, отсутствие
вложенных модалок, близнецы `src/` ↔ `api/`). Мержит Claude — Codex не мержит сам.
SQL-файл из PR применяется отдельно, до мержа кода, и должен быть совместим со старым
кодом.
