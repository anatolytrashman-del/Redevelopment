# Карточки застройщиков на странице БЦ

Владелец, 2026-09-20: у половины бизнес-центров застройщик — нормальная
компания с сайтом, для таких сделать развёрнутую карточку (логотип, описание,
контакты, сайт) сразу под главным блоком карточки БЦ, по образцу блока
"Застройщик района" на гиде по Минск Миру (`DistrictGuidePage.tsx`,
`id="developer"`). Из главного блока короткую строку "Застройщик: ..." убрать
(поле `developer` осталось — его использует FAQ и старое место, просто не
рендерится отдельной строкой в шапке).

Пилот сделан на «Футурисе», затем разобрана вся база (141 БЦ) на предмет "где
ещё есть нормальный застройщик".

## Как это устроено технически

- `data/businessCenters.ts` — `BusinessCenter.developerInfo: DeveloperInfo | null`,
  `DeveloperInfo = { logoUrl, description, phone, address, hours, website }`
  (все поля `string | null`). Короткое поле `developer` (строка) — отдельное,
  не трогается.
- `lib/businessCentersApi.ts` — колонка `developer_info` (jsonb) в
  `fromRow`/`toPayload`.
- `components/marketOffers/BusinessCentersAdminTab.tsx` — необязательный блок
  полей "Карточка застройщика" в форме БЦ (после поля "Застройщик / УК").
- `pages/BusinessCenterDetailPage.tsx` — сама карточка, id="developer",
  рендерится сразу под главным блоком, когда `developerInfo` не null;
  добавлена в оглавление страницы (`SECTION_LABELS`/`SECTION_ICONS`,
  `pageSections`) и отдельной ссылкой в список "Источники" внизу страницы
  (`developerWebsiteUrl`, не путать с `centerWebsiteUrl` — сайтом самого
  здания, который отдельное поле `website` на BusinessCenter).
- Заполнение данных — SQL напрямую через Supabase Management API (не через
  админку, т.к. это разовый бэкфилл по многим записям), с последующей
  отметкой `deploy_debounce` (`scope='business_centers'`, `consumed_at=null`),
  чтобы очередной часовой pg_cron подхватил новые карточки при пересборке.
  Код (`triggerPublicRebuild`) делает то же самое при обычном сохранении
  через админку — так что для будущих единичных правок можно и через форму.

## Критерий "нормальный застройщик" (планка для карточки)

Карточку делаем ТОЛЬКО когда есть:
1. узнаваемая, реально существующая компания (не голая SPV под одно здание);
2. у неё есть СВОЙ рабочий сайт (не путать с сайтом самого объекта — хотя
   иногда это одно и то же, если сайт содержит информацию именно о компании,
   а не только о здании);
3. независимое подтверждение хотя бы с одной стороны (realt.by, domovita.by,
   prometr.by, megapolis-real.by, 2ГИС, пресса) — не только собственные слова
   компании о себе.

НЕ подходят: госорганы/госпредприятия-балансодержатели (это не девелоперский
бренд), иностранные заказчики реконструкции без публичного сайта, компании,
известные в другой отрасли (не как застройщик), SPV с юрадресом = адрес
самого здания и без других проектов.

## Правило про негатив (важно, действует всегда)

Владелец, 2026-09-20: **явный негатив про любого застройщика — не решать
самому, выносить на отдельное согласование** перед тем как включать/не
включать в карточку. **Про Dana Holdings — вообще никакого негатива никогда**,
это отдельное жёсткое правило сверх общего.
На практике: если ресёрч (агент) находит негатив — компания просто получает
пометку в этом файле, карточка не делается/не публикуется с негативом, пока
явно не решено иначе. Один прецедент уже был: БЦ «Премьер» (ООО
«Си-Трейдинг») — дефолт по двум облигационным выпускам в 2024 году; владелец
решил: карточку делать, дефолт не упоминать. Это разовое решение по этой
компании, не общее правило "негатив можно скрывать по умолчанию" — каждый
следующий случай снова на согласование.

## Дальше (не начато)

**115 из 141 БЦ в базе вообще без указанного застройщика** (`developer IS NULL
OR developer = ''`). Это отдельная, кратно более крупная задача — сначала
нужно ПО КАЖДОМУ такому зданию выяснить, кто вообще застройщик (сейчас этого
нет даже в виде короткой строки), и только потом решать, "нормальный" ли он
для карточки. Не начиналось вовсе. Список самих БЦ без застройщика — берётся
запросом:

```sql
select slug, name, address from business_centers
where developer is null or developer = '' order by slug;
```

Также по ходу разбора всплыло (не относится к застройщикам, отдельный
маленький баг): в `src/lib/businessCenterDisplay.ts`
(`BUSINESS_CENTER_WEBSITE_OVERRIDES`) домен `sit.by` помечен как нерабочий
(`null`), но при разборе БЦ «Премьер» агент нашёл его живым и обновляемым
(новости за 2024-2025). Не трогал — нужна отдельная проверка глазами и правка
теста `businessCenterDisplay.test.ts`, который сейчас явно ожидает `null` для
`https://sit.by`.

2. Решить, продолжать ли "115 без застройщика" (или что-то из списка "можно
   пересмотреть" выше — titul, pushkinsky).
3. Если да — исследовать пачками через параллельных агентов (WebSearch,
   egress на `.by`-домены обычно заблокирован, агенты работают по сниппетам
   и агрегаторам realt.by/domovita.by/prometr.by/megapolis-real.by/2ГИС),
   так же, как в этом заходе — 3-4 компании на агента, без прямого доступа к

5. Записи в БД — сам, через Supabase Management API (см.
   `CLAUDE.md` → "SQL-миграции"), не забыть пометку `deploy_debounce`.
6. Код менять не нужно — компонент карточки уже общий и рендерит любые
   заполненные `developerInfo` без правок.
