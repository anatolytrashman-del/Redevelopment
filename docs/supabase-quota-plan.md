## Что уже сделано

- [x] **Найдена и закрыта причина дублей.** Во всех двенадцати загрузчиках
      `crypto.randomUUID()` стоял ВНУТРИ функции, которую `withRetry`
      вызывает заново на каждой попытке (`retries = 3`, то есть до четырёх
      заходов). Таймаут загрузки 60 с, веб-архив на 22 МБ в него не
      укладывается: `withTimeout` отдаёт ошибку, HTTP-запрос на сервере
      доходит, повтор льёт тот же файл под новым именем. С одного нажатия —
      до четырёх копий, форма записывает только последнюю. Имя теперь
      считается снаружи, у `.upload` стоит `upsert: true`. Правило записано
      в `CLAUDE.md` и в шапку `withRetry.ts`. Прод: `630c5ec`.
- [x] **Отключено хранение веб-архивов.** `parseBusinessCenterSnapshot(file)`
      читает локальный `File` через `arrayBuffer()` — организации, рейтинг и
      отзывы достаются в браузере ещё до загрузки. Сам архив после разбора не
      перечитывает никто: публичные страницы к нему не обращаются,
      повторного разбора нет, `map_snapshot_files` виден только в админке
      строкой со ссылкой. Теперь файл разбирается и не сохраняется. Заодно
      убрана фоновая загрузка (её добавили тем же утром под жалобу «файлы
      грузит уже секунд 40») — грузить стало нечего, ожидание исчезло
      совсем. Прод: `634f845`.
- [x] **Владелец удалил 15 сиротских веб-архивов** (337 МБ), на которые не
      ссылалась ни одна из 693 текстовых/jsonb-колонок базы.

## Как удалять (важно)

Удаление ОБЯЗАНО идти через Storage API, а не через `delete from
storage.objects`: SQL убирает только строку метаданных, сами байты остаются
в хранилище, и место не освобождается — получится видимость уборки.

Доступные пути:

1. **Панель Supabase** — Storage → `object-documents` → отсортировать по
   размеру → отметить → удалить. Работает всегда, ничего настраивать не надо.
2. **`SUPABASE_SERVICE_ROLE_KEY` в окружении сессии.** Владелец добавил его
   2026-09-20; переменные подхватываются со СЛЕДУЮЩЕЙ сессии. Тогда удаление
   делается запросом `DELETE /storage/v1/object/object-documents` с телом
   `{"prefixes": [...]}`.

Чего НЕ делать: временно выдавать `anon` право на удаление ради уборки.
Пробовал 2026-09-20 — классификатор безопасности блокирует, и справедливо:
это раздача прав в общем бакете.

## Отдельно: удаление файла в админке не удаляет файл

Кнопка «убрать файл» в карточке БЦ (`mapSnapshotFiles`) вычёркивает ссылку из
формы, но объект в Storage остаётся. То есть каждое «убрал лишнее» плодит
сироту. Не чинил — после отказа от загрузки архивов новых записей там не
появляется, но если когда-нибудь вернём хранение файлов в этом поле, чинить
придётся сразу.
