## Претензия владельца

Скриншот блока FAQ на живом сайте: ответ на вопрос «Как весь каталог распределён по
районам?» — это один абзац, где подряд через `;` идут 9 районов, и у каждого по три числа
(штук, площадь, медиана аренды). Дословно: «Много цифр в 1 блоке не читаются вообще.
Делай понятно и интересно для человека, как в инфостиле Ильяхова».

Сam текст сейчас собирается кодом (строка ~766–770):

```ts
if (Object.keys(districtTotals).length) add('Как весь каталог распределён по районам?', Object.entries(districtTotals).map(([district, n]) => {
  const area = (centers ?? []).filter((c) => c.district === district).reduce((sum, c) => sum + (c.totalArea ?? 0), 0);
  const rate = (officeSnapshots ?? []).find((s) => s.sliceType === 'district' && s.deal === 'rent' && s.sliceKey === district)?.median;
  return `${district}: ${n} БЦ${area > 0 ? `, ${Math.round(area).toLocaleString('ru-RU')} м² по заполненным площадям` : ''}${rate != null ? `, медиана аренды $${rate}/м²` : ''}`;
}).join('; '));
```

То есть на выходе буквально «Центральный: 20 БЦ, 494 027 м² по заполненным площадям,
медиана аренды $16.09/м²; Октябрьский: 10 БЦ, 208 166 м²...» — и так все районы подряд.
Это не единственный такой ответ: у вопроса «Как здания выборки распределены по классам?»
та же болезнь в миниатюре (`Класс А — 15; Класс B — 61; ...`).

## Что значит «инфостиль Ильяхова» здесь конкретно

Не эзотерика, а набор проверяемых требований:

1. **Не вываливай все цифры в одном перечислении.** Если фактов больше 3–4, вытащи
   главное (максимум/минимум/заметный контраст) и скажи это простым предложением, а не
   перечисли всё подряд через `;`. Пример разницы:
   - Было: «Центральный: 20 БЦ, 494 027 м², медиана $16.09/м²; Октябрьский: 10 БЦ,
     208 166 м², медиана $12.89/м²; Советский: 20 БЦ, ...» (и так 9 раз).
   - Стало (пример направления, не готовая формулировка — числа подставляй настоящие
     через тот же код): «Больше всего зданий в Центральном и Московском районах — по
     20+ БЦ в каждом, меньше всего — в Заводском и на Великом Камне. Аренда дороже
     всего в Центральном и Первомайском (медиана $16/м²), дешевле всего — в Советском
     ($7.6/м²)». Короткие предложения, конкретика, ничего не выдумано — то же самое
     `districtTotals`/`officeSnapshots`, просто выбраны крайние и заметные значения
     вместо сплошного перечисления.
2. **Конкретность вместо канцелярита.** Не «представлены следующие данные», а прямое
   утверждение. Не «по заполненным площадям» бюрократическим языком в каждой строке —
   если оговорка важна (не у всех зданий известна площадь), скажи её один раз в начале
   ответа, а не при каждом районе.
3. **Активный залог, короткие предложения.** Не нанизывай придаточные и не пиши одно
   30-словное предложение с пятью запятыми.
4. **Никаких выдуманных фактов и никакой потери данных.** Числа и названия — ровно те,
   что даёт код (`districtTotals`, `centers`, `officeSnapshots`, `marketStats` и т.п.),
   без округления «на глаз» сверх уже принятого в коде (`Math.round`, `.toLocaleString`).
   Если сокращаешь перечисление до «главного», не выбрасывай данные молча — упомяни
   общее число районов/классов, чтобы читатель понимал, что показан не весь список
   («… и ещё N районов» подойдёт, если формулировка того требует).
5. **Ответ остаётся простой строкой (`string`), не JSX.** `faqItems` — это
   `{ question: string; answer: string }[]`, значение уходит и в видимый текст, и в
   `FAQPage` JSON-LD (модуль `setFaqJsonLd` его использует как есть) — переносы строк
   в `\n` внутри строки допустимы, но помни, что видимый рендер (не твоя часть задания)
   схлопывает пробелы в HTML, так что перенос там не сработает визуально — не полагайся
   на `\n` как на единственный способ читаемости, решай форматулировкой предложения.

## Что переписать

Пройдись по всем вопросам в `faqItems` (их около 12) и перепиши формулировки в этом
духе, но **основную работу сделай на двух самых плотных ответах**:

1. «Как весь каталог распределён по районам?» — главный виновник, см. пример выше.
2. «Как здания выборки распределены по классам?» — тот же принцип в миниатюре: не
   «Класс А — 15; Класс B — 61; Класс B+ — 28; Класс C — 37», а короткое предложение
   про то, какого класса больше всего, а какого меньше (те же числа, другая подача).

Остальные вопросы (сколько зданий, площадь, метро, аренда, застройка, методология
медианы, ставки рынка, «где посмотреть управление», «как работают фильтры», «что значит
параметр не известен») уже написаны более-менее нормальной прозой — пройдись по ним и
поправь только то, что режет глаз канцеляритом или слишком длинным предложением; не
переписывай ради переписывания то, что уже читается нормально.

**Не трогай:**
- список и порядок самих вопросов (какие `add(...)` вызываются и при каких условиях —
  логику "если данных нет — вопроса нет" не меняй);
- переменные, из которых берутся данные (`scopeLabel`, `marketStats`, `districtTotals`,
  `officeSnapshots`, `rentMethodology`, `underConstructionNames`, ставки рынка) — их
  вычисление в файле ВЫШЕ `faqItems` не меняй, только то, как их значения собираются в
  текст ответа;
- сам JSX рендера FAQ ниже по файлу (это часть другой задачи).

## Критерий готовности

- Чистый `npm run build:app`.
- Диф ограничен телом `useMemo` `faqItems` (может задеть одну-две соседние строки
  форматирования, не больше).
- В ответе про районы больше нет плоского перечисления всех районов через `;` с тремя
  числами у каждого — есть выбор главного (крайности/контраст) простым предложением.
- Ни одно число/название района/класса не изменилось по сравнению с тем, что реально
  считает код (не выдумано, не округлено иначе).
- Когда закончишь — перечисли, что именно поменял в каждом вопросе (можно коротко,
  списком), и если что-то из задания решил не делать — скажи прямо, что и почему.
