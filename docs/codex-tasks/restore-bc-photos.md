# Отдать финальные фото по всем бизнес-центрам

## Зачем

Пакет фото БЦ с вывесками собирался на ветке `codex/bc-photo-parus-victoria-v`.
Ветку удалили, её коммиты GitHub больше не отдаёт, и в `preview`/прод эта
работа НИКОГДА не вливалась — на сайте до сих пор старые фото. Нужно вернуть
результат в репозиторий.

## Что сдать

Финальные фото **по всем бизнес-центрам**, которые ты обработал, — не частями.
Где делалось несколько версий или попыток, в репозиторий кладётся **только
финальная**: ни черновиков, ни альтернатив рядом.

Один комплект на здание, ровно три файла, имена строго такие:

```
public/images/business-centers/<slug>.jpg
public/images/business-centers/<slug>.webp
public/images/business-centers/<slug>-card.webp
```

Никаких `-v2`, `-new`, `-final`, `-2026` и прочих суффиксов: финальная версия
перезаписывает файл по существующему имени.

## Здание на пр-те Победителей, 59 — частный случай

Слаг у него `v`, но называется оно теперь «Бизнес-центр «Столица»», и колонка
`photos` в базе указывает на `/images/business-centers/stolitsa.jpg`.

Значит финальное фото этого здания кладётся в `stolitsa.jpg`, `stolitsa.webp`,
`stolitsa-card.webp` — **не** в `v.*`. Если у тебя финальная версия лежит под
именем `v.*`, переименуй её в `stolitsa.*` и файлы `v.*` не добавляй вовсе.
Тогда базу править не придётся.

## Как сдать

Ветка от СВЕЖЕГО `preview` (`git fetch origin` обязательно — ТЗ появилось
позже, чем ты начал) и PR в `preview`. В описании PR перечисли, по каким
зданиям фото обновлены.

## Чего НЕ делать

- не трогать код, миграции и таблицу `business_centers` — базу правит Claude,
  у тебя к ней доступа нет;
- не переименовывать существующие файлы: на путь
  `/images/business-centers/<slug>.jpg` завязана колонка `photos`, переименование
  обрушит фото на странице;
- не добавлять вторых комплектов на одно здание.
