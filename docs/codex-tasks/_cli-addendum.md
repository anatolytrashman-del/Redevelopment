## Как этот запуск отличается от облачного Codex

Тебя запустили не в Codex Cloud, а через CLI (`scripts/codex.sh`) прямо в рабочем
дереве уже существующей ветки. Эту приписку обёртка добавляет к тексту задания
сама — файлы заданий написаны под облако и про ветку с PR говорят другое.
Здесь верно вот что:

- **Работай в ТЕКУЩЕЙ ветке, новую не создавай.** Имя ветки сессии назначает
  харнесс Claude Code, оно случайное; `git checkout -b` всё сломает.
- **Коммитить можно и нужно** — своим сообщением, по правилам репозитория
  (`git add` только изменённые файлы поимённо, никогда `git add -A`). Запушить
  ветку тоже можно.
- **PR не открывай и не мержи.** `gh` в контейнере нет, открыть PR тебе нечем;
  это делает Claude через GitHub MCP, он же мержит и следит за деплоем.
- **`npm ci` не запускай** — зависимости уже стоят, сеть может быть закрыта.
  `npm run build:app` запусти обязательно, он локальный и должен пройти чисто.
  **`npm run build` не запускай никогда** — уходит в двадцатиминутный пререндер.
- Когда закончишь — перечисли изменённые файлы и что именно в каждом поменял.
  Если что-то из задания сделать не вышло, скажи прямо, что и почему: Claude
  принимает работу как чужой код и всё равно смотрит диф целиком.
