## Перед стартом — сверься с репозиторием, не с этим списком вслепую

Список собран по данным базы на момент постановки задачи. Обнови ветку
(`git fetch origin && git checkout preview && git pull`) и посмотри
реальное содержимое `public/images/business-centers/` — если у кого-то из
списка уже лежит нормальное фото здания (не общая ссылка на организацию /
не картинка не по адресу), а не заглушка, пропусти его и укажи это в PR.

## Что сдать

Один комплект на здание, ровно три файла, имена строго такие:

```
public/images/business-centers/<slug>.jpg
public/images/business-centers/<slug>.webp
public/images/business-centers/<slug>-card.webp
```

Основные изображения — 1200×1200, карточки — 640×640 (как в PR #363).
Никаких `-v2`, `-new`, `-final` и прочих суффиксов — финальная версия
перезаписывает файл по существующему имени. Где делалось несколько версий,
в репозиторий кладётся только финальная.

Не сдавай частями — жди, пока не закроешь всё, что реально можешь закрыть
по этому списку, и сдавай одним PR (как было с PR #363).

## Как сдать

Ветка от СВЕЖЕГО `preview`, PR в `preview`. В описании PR перечисли:
- по каким зданиям из списка фото обновлены;
- какие из списка пропущены и почему (нет фото / уже было нормальное фото
  на месте `<slug>.jpg`).

## Чего НЕ делать

- не трогать код, миграции и таблицу `business_centers` — базу правит
  Claude, у тебя к ней доступа нет;
- не переименовывать существующие файлы: на путь
  `/images/business-centers/<slug>.jpg` завязана колонка `photos`,
  переименование обрушит фото на странице;
- не добавлять вторых комплектов на одно здание;
- не трогать файлы зданий не из этого списка.
