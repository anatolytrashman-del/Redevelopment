# Страница поставщика по новому макету (тред «Закупки», 2026-09-28)

Переверстать страницу компании-поставщика `src/pages/SupplierDetail.tsx`
(`/admin/suppliers/:id`) по утверждённому владельцем макету
`tmp/mockups/supplier-card.html` (открой и прочитай целиком). Пример реальных
данных профиля — `tmp/mockups/kraskoff-site-profile.json`.

Всё, что страница умеет сейчас, должно остаться рабочим: стоп-лист,
перепроверка реестра, «Обновить сайт», объединение с дублем, контакты
(добавить/изменить/убрать), условия КП, заказы, проверка, активность.
Меняется раскладка и добавляются данные из профиля сайта.

## 1. Данные

В таблице `suppliers` уже есть колонка `site_profile jsonb` (схема — в
`scripts/supplier-profile/extract-brief.md`). В `src/data/suppliers.ts`:

- добавь `interface SupplierSiteProfile` по этой схеме, все поля
  необязательные (в старых строках части полей нет): `company_name`,
  `legal_entities[] {name, inn, ogrn, kpp, legal_address}`, `founded_year`,
  `about`, `production {has_own_production, sites[], capacity, certifications[]}`,
  `own_brands[]`, `product_kinds[]`, `resold_brands[]`,
  `products[] {name, brand, article, unit}` (цену НЕ описывать и нигде не
  показывать), `contacts {phones[] {number,label}, emails[] {email,label},
  messengers[] {type,value}, social[]}`, `addresses[] {type, city, address,
  hours}`, `regions[]`, `terms {wholesale, min_order, delivery, payment,
  dealer_program}`;
- `Supplier.siteProfile: SupplierSiteProfile | null`, `SupplierRow.site_profile?: unknown`;
- маппинг в `fromRow` в `src/lib/suppliersApi.ts` (null, если не объект).
  `SupplierInput` поле не включает — форма его не затирает (так уже сделано
  с остальными полями профиля, посмотри рядом).

## 2. Шапка (одна карточка `Card`)

- Название крупно; рядом бейдж типа из `SUPPLIER_KIND_LABELS`
  (`supplier.supplierKind`) с иконкой `Factory` — зелёный (`success`) для
  `manufacturer`, нейтральный для остальных; бейджи «Проверена человеком»,
  риск (как сейчас), «в стоп-листе».
- Строка мета: ссылка на сайт (синяя, `text-info-text`, не красная), город
  первого адреса профиля, «Работает с N года» (`founded_year`), «Возит: …»
  (`regions`, первые 3).
- Справа действия: основная кнопка «Написать» (текущая ссылка на переписку),
  остальные четыре действия (Перепроверить реестр, Обновить сайт, Объединить
  с дублем, В стоп-лист / Вернуть в работу) — в меню «•••»
  (кнопка-иконка `MoreHorizontal`, выпадающий список под ней, закрытие по
  клику вне и по Escape; НЕ модалка).
- Полоса цифр внизу шапки на всю ширину, 4 ячейки с разделителями, как в
  макете: своих марок (`own_brands.length`), видов товара
  (`product_kinds.length`), позиций в каталоге (`products.length`), КП
  (число `quotes` и дата последнего). Нет профиля — ячейки с «—».
- Карточка стоп-листа остаётся под шапкой, как сейчас.

## 3. Вкладки

Порядок: Обзор, Каталог, Переписка, КП и цены, Заказы, Проверка, Активность.
Вкладка «Контакты» убирается — её содержимое переезжает в правую колонку
«Обзора» (см. ниже), слаг `contacts` при открытии старой ссылки ведёт на
«Обзор». Новая вкладка «Каталог», слаг `catalog`.

Вид вкладок — сегментированный переключатель, как в макете: подложка
`bg-surface-muted rounded-full p-1`, активная — белая с тенью, без красного.
Рядом с названием серым число, где оно есть (Каталог — товары, Переписка —
письма, КП — КП, Заказы — заказы). На телефоне горизонтальный скролл
внутри своей полосы, страница вбок не едет.

## 4. «Обзор»

Две колонки на `lg` (`grid-cols-[minmax(0,1fr)_340px]`), одна на узком.

Левая:
1. «Что производит сам» для `manufacturer`/`brand_owner`, «Что продаёт» для
   остальных. Внутри подзаголовки мелкими капсом:
   - «Свои марки» — чипы в нейтральной рамке (`border border-border-strong
     bg-surface`, полужирный), в чипе серым число товаров этой марки в
     `products`; показывать первые 14, дальше кнопка «ещё N» разворачивает;
   - «Виды товара» — серые чипы, первые 12 + «ещё N»;
   - «Чужие марки» — для дилеров и магазинов, если есть `resold_brands`.
   - Под ними абзац `about`, если есть.
   Нет профиля — показывать как сейчас «Что поставляет» по снимку сайта.
2. «Участвует в закупках» — текущий блок как есть.
3. «Наша история» — 5 последних событий из того же `activity`, что во
   вкладке «Активность» (дата, заголовок, строка деталей, ссылка), внизу
   ссылка «Вся активность» на вкладку.

Правая колонка (компактные карточки):
1. «Контакты»: почта карточки (`supplier.email`) первой с пометкой
   «пишем сюда»; затем почты и телефоны профиля с подписями (`label`),
   без дублей с уже показанными; у каждой строки кнопка «Копировать»
   (`navigator.clipboard.writeText`, при ошибке — ничего не ломать, текст
   выделяемый); телефоны форматировать `formatPhoneDisplay`. Ниже люди из
   `supplier_contacts` (то, что было во вкладке «Контакты») с теми же
   действиями добавить/изменить/убрать и той же `ContactFormModal`.
   Мессенджеры — существующим `MessengerChips`.
2. «Адреса»: адреса профиля по типам с русскими подписями (office —
   «Офис», production — «Производство», warehouse — «Склад», showroom —
   «Шоурум», store — «Магазин», legal — «Юридический»), часы работы серым.
   Если тип `manufacturer`, а адреса производства нет — пунктирная плашка
   «Производство: адрес на сайте не указан».
3. «Условия»: опт, мин. заказ, доставка, оплата, дилерам из `terms`
   (пустые не показывать), под ними текущие условия из КП (`termsNotes`).
4. «Реквизиты»: юрлица профиля (название, ИНН, ОГРН с «Копировать»); если
   профиля нет — `supplier.inn`.
5. Текущие «Благонадёжность» и «Насколько свежие данные» — переносятся сюда
   без изменений логики.

«Цены с сайта», «Документы», «Артикулы» и «Почему завод» НЕ выводить
нигде — владелец их убрал из макета.

## 5. «Каталог»

Таблица товаров `siteProfile.products`: товар, марка, артикул, ед. — без
цен. Сверху поиск по названию/артикулу (`SearchInput` из `components/ui`) и
фильтр по марке (`Select`). Подпись: «Товары с сайта {host} на {дата
profiledAt}. Цены с сайта не показываем — они быстро устаревают.» Пусто —
«Каталог с сайта ещё не собран».

## 6. Правила

- Красный (`primary`/`danger`) — только на действиях, которые его уже имели,
  и на стоп-листе/риске. Никаких красных чипов, вкладок и ссылок.
- Вложенных модалок не делать (см. CLAUDE.md).
- `npx tsc -b` и `npm run lint` чистые, `npm run build:app` собирается.
- Существующий мок-тест, если использует `SupplierDetailView`, обнови под
  новые пропсы (`siteProfile` в заглушке поставщика).
