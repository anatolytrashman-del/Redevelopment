# Задача 11 — вернуть нормальный вид карточек каталога БЦ

Источник: `docs/bc-catalog-master-plan.md`, раздел «Задача 11». Прочитай его перед
началом (он короткий), плюс `AGENTS.md` в корне.

## Цель

Владельцу не нравится, во что превратились карточки каталога `/minsk/bcminsk`:
они стали мелкими и плотными. Надо вернуть прежнее, более крупное оформление
карточки, сохранив нынешнее СОДЕРЖИМОЕ. Возвращается вид, а не факты.

## Что уже проверено с нашей стороны — не тратьте время заново

Перед выдачей задания прод `/minsk/bcminsk` был снят браузером на ширинах
360 / 1280 / 2000 px по пререндеренной разметке:

- карточки НЕ схлопнуты: высота карточки 365 px, фотоблок 163–183 px,
  заголовок и строки фактов на месте;
- сетка на 1280 и 2000 px даёт четыре колонки по 292 px (контейнер упирается
  в свою максимальную ширину, поэтому на 2000 px колонок тоже четыре);
- на 1024–1279 px работает `lg:grid-cols-3` — это и есть «три колонки на
  широком окне» со скриншота владельца, а не поломка.

Известная историческая причина схлопывания — `content-visibility: auto` плюс
`contain-intrinsic-size: auto 420px` на карточке (владелец присылал такой же
скриншот 2026-09-16). Она уже убрана коммитом `3798036`, в `src/` этих свойств
нет. В прод-бандле CSS правила `.[content-visibility:auto]` и
`.[contain-intrinsic-size:auto_420px]` ещё генерируются — но только потому, что
эти строки встречаются в тексте `PAGESPEED_PLAN.md` и `docs/session-journal.md`,
а Tailwind v4 сканирует и markdown. Ни на одном элементе классы не висят,
в отрендеренном HTML их нет. **Эти md-файлы не править** — это история, а не код.

Вывод: отдельной «настоящей причины» искать не надо, скриншот владельца снят до
удаления `content-visibility` либо со старым бандлом в кэше браузера. Работа
сводится ко второму пункту задачи 11 — вернуть крупный вид.

## Что сделать

Файл: `src/pages/BusinessCentersMinskPage.tsx`.

Эталон прежнего вида — `git show 852738e^:src/pages/BusinessCentersMinskPage.tsx`,
функция `BusinessCenterCard`. Оттуда берётся ТОЛЬКО оформление.

1. Сетка выдачи карточек (сейчас строка ~1071):
   `grid grid-cols-1 gap-4 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4`
   → `grid grid-cols-1 gap-5 sm:grid-cols-2 xl:grid-cols-3`.
   Больше трёх колонок быть не должно ни на какой ширине.
2. Фотоблок карточки: `aspect-[16/9]` → `aspect-[16/10]`.
   Заодно это снимает рассогласование с `PhotoBlock` в
   `src/components/businessCenters/BusinessCenterVisuals.tsx`: у варианта `card`
   там стоят `width={640} height={400}`, то есть 16:10, и при контейнере 16:9
   браузер до загрузки фото резервировал неверную высоту. Сам `PhotoBlock`
   править не нужно — после возврата 16:10 он снова согласован; проверьте это
   и, если поправите комментарий, только комментарий.
3. Заголовок карточки: `text-sm` → `text-base`, и выводить полное название
   `center.name` вместо укороченного `shortName(center)`.
   Если после этого `shortName` больше нигде в файле не используется — убрать
   его из импорта, иначе упадёт lint.
4. Отступы в теле карточки: контейнер тела `gap-2` → `gap-2.5`,
   внутренний блок строк фактов `gap-1` → `gap-1.5`.

## Чего НЕ делать

- Не менять состав фактов на карточке (метро, площадь/этаж, ставка и лоты,
  2ГИС/УК/парковка), не трогать авто-бейдж, кружок индекса и кнопку «Сравнить» —
  их судьба решается другими задачами плана.
- Не трогать переключатель видов, `CatalogTable.tsx`, `CatalogMap.tsx`,
  `CatalogCompare.tsx`, фильтры и URL-состояние — это задачи 8 и 9, они пойдут
  отдельными ветками, и пересечение в этом файле создаст конфликт.
- Не трогать `PAGESPEED_PLAN.md` и `docs/session-journal.md`.
- Не трогать `.github/workflows/`.
- Миграций тут нет и не нужно.

## Критерий готовности

- `npm run build:app` проходит чисто (`npm run build` не запускать никогда).
- `npm run lint` чистый.
- В диффе только `src/pages/BusinessCentersMinskPage.tsx` (плюс, если нужно,
  комментарий в `BusinessCenterVisuals.tsx`) и строка в `docs/session-journal.md`.
- В `docs/session-journal.md` добавить одну строку `- **2026-09-17** — ...`
  в НАЧАЛО списка.
