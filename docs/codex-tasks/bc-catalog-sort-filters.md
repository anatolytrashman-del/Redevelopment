# Задание: сортировка и фильтры каталога бизнес-центров

Каталог БЦ Минска — маршрут `/minsk/bcminsk`. План: `BCMINSK_SEO_PLAN.md`, раздел
«Каталог — приоритет 1», пункт про сортировку и дополнительные фильтры.

Нужна сортировка по площади, году постройки, классу, метро и алфавиту плюс
дополнительные фильтры (в плане перечислены, начиная с площади).

**Состояние сортировки и фильтров обязано попадать в URL** — это SEO-страница,
отфильтрованную выдачу должно быть можно расшарить, а поисковику — проиндексировать.
Открытая по ссылке страница должна восстанавливать ровно то состояние, что было у
отправителя.

Заодно проверь, что уже сделано, — в том же файле есть раздел «Что уже сделано
(не переделывать)».

## Готово, когда

`npm run build:app` чистый; каждая комбинация сортировки и фильтров имеет свой URL и
восстанавливается из него; на пустой выдаче страница объясняет, что ничего не нашлось,
а не показывает пустоту.

## Общие правила (обязательны)

Репозиторий: `anatolytrashman-del/Redevelopment`. Перед началом прочитай `AGENTS.md`
в корне — там правила проекта и грабли, на которые здесь уже наступали.

- Ветку бери от `claude/redevelopment-platform-prototype-oodobu` (это прод-ветка,
  НЕ `main`), имя своей ветки — с префиксом `codex/`.
- Проверка перед PR: `npm ci && npm run build:app`. **Никогда не запускай
  `npm run build`** — он уходит в полный пререндер на двадцать минут.
- `git add` только изменённые файлы поимённо, никогда `git add -A`.
- PR открывай в `claude/redevelopment-platform-prototype-oodobu`, описание по-русски.
  **PR не мержи** — принимает и мержит другая сторона.
- Миграции в базу не применяй: если нужна схема, положи SQL-файл в
  `supabase/migrations/YYYYMMDD-<тема>.sql`, закончи его строкой
  `NOTIFY pgrst, 'reload schema';` и упомяни файл в описании PR.
- Секретов и сети у тебя нет: в Supabase, Resend, Vercel, Google и Telegram не ходи.
