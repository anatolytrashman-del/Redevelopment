# Задача 2 — не клеветать на здание отсутствием объявлений

Источник: `docs/bc-catalog-master-plan.md`, раздел «Задача 2». Перед началом прочитай
`AGENTS.md` в корне.

## Цель

Отсутствие активных объявлений у нас сейчас в разных местах подаётся по-разному, и
местами читается как «в здании нет свободных помещений». Это разные вещи: **у нас нет
данных, а не у здания нет площадей.** Нужна одна честная формулировка, один раз на
страницу, с указанием источника и даты.

## Что сделать

### 1. Единая формулировка

Базовая формулировка везде одна: **«Активных предложений в наших источниках нет»**,
рядом — какие это источники (Kufar, Realt) и когда обновлялись данные. Дату брать из
того, что уже есть в данных объявлений/снимков (`src/data/businessCenterOffers.ts`,
`src/lib/businessCenterOffersApi.ts`); поля с датой нет — сказать про источники без
даты, дату НЕ выдумывать.

Места, которые надо привести к ней (пройдись grep'ом, список не исчерпывающий):

- `src/pages/BusinessCenterDetailPage.tsx`, блок «Сейчас предлагается» (~строка 996):
  текст «На Kufar и Realt сейчас нет активных объявлений…» — переформулировать;
- `src/pages/BusinessCentersMinskPage.tsx`, карточка каталога: строка факта
  «объявлений сейчас нет»;
- `src/components/businessCenters/BusinessCenterMarketBlocks.tsx` — все места, где
  пустая выборка объявлений превращается в текст.

### 2. Убрать повторы и пустые таблицы

На странице здания без объявлений сообщение об их отсутствии не должно встречаться
дважды-трижды подряд, и не должно оставаться пустых таблиц с одними заголовками.
Один раз сказать достаточно.

### 3. Убрать «нет объявлений» из минусов здания

`src/lib/businessCenterVerdict.ts`, строка ~88:

```ts
if (lots === 0) cons.push('Активных объявлений на Kufar и Realt сейчас нет — придётся писать в УК напрямую');
```

Это ровно то, против чего сам файл предупреждает четырьмя строками выше: «Отсутствие
данных минусом не считается: мы не знаем, а не „там плохо“». Пункт из `cons` убрать.
Остальные пороги в этом файле НЕ трогать — ими занимается задача 3, она пойдёт
отдельной правкой.

### 4. Диапазон свободных площадей

Плитка «Свободные площади» в `BusinessCenterMarketBlocks.tsx` (~строка 411) заполнена
только у 30 зданий из 143 — у остальных источник пишет «подлежат уточнению» и в базе
стоит `null` (см. комментарий в `src/data/businessCenters.ts:169`).

Две правки:

- диапазон не подтверждает наличие любого размера внутри него. Подпись плитки должна
  это говорить: это диапазон из справочника prometr.by, а не подтверждённый перечень
  доступных блоков;
- там, где значения нет, плитка сейчас просто не выводится. Это нормально — не
  заменять её на «нет свободных площадей». Если где-то по коду пустое значение
  превращается в «0» или в «нет» — поправить.

Внимание к граблям из `AGENTS.md`: `!value` считает `0` отсутствием данных. Здесь
это живой риск — проверяй `!= null`, а не `!value`.

## Чего НЕ делать

- Не трогать сам расчёт стоимости по лотам — это задача 1, она уже сделана и лежит
  в этой же ветке; если увидишь свежий код по активным объявлениям, встраивайся в
  него, а не переписывай.
- Не трогать пороги плюсов/минусов и вердикт (кроме пункта 3 выше) — задача 3.
- Не трогать медали, ранги и FAQ — задача 4.
- Не трогать `.github/workflows/`, миграций тут нет.

## Готово, когда

`npm run build:app` и `npm run lint` чистые; на странице здания без объявлений ровно
одно сообщение о том, что предложений нет в наших источниках, с названием источников;
пустых таблиц не осталось; «нет объявлений» больше не числится минусом здания.
Одна строка в начало списка `docs/session-journal.md`.
