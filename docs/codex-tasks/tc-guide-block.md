## Блок «Что где в {название}»

Пункт в оглавлении «Что где», id секции 'floors' оставить.
Подзаголовок: «{N} уровней, около {M} магазинов, кафе и сервисов». N — число этажей на
табло, M — число «магазиноподобных» организаций, округлённое вниз до десятков
(«около 270»). Части без данных не выводить, склонения через существующий `pluralRu`.

1. **Карточка поиска** (белая, скруглённая). Поле «Найти магазин»: без учёта регистра,
   ё=е, поиск подстроки. Пока человек печатает, до 5 строк результата: имя жирным +
   красная плашка «2 этаж» (или приглушённое «этаж не указан») + приглушённое
   «рядом A, B, C». «Рядом» — до 3 других организаций того же этажа: сначала с той же
   исходной категорией, потом по наибольшему reviewCount, мусор отфильтрован (см.
   фильтр ниже). Выбор строки или единственное точное совпадение подсвечивает этаж на
   табло: тёмно-красный фон строки + маленькая красная метка «{Имя} здесь». Ничего не
   нашлось — «Не нашли „…“». Под полем «Часто ищут:» — 5 ссылок с пунктирным
   подчёркиванием: топ-5 магазиноподобных организаций по reviewCount, клик вписывает
   имя в поиск. Полного списка арендаторов на странице нет нигде.
2. **Табло этажей** (тёмная карточка как в макете, стиль `bg-[#1b1c20]`, белый текст,
   крупные номера этажей слева, «−1» с настоящим минусом). Строки сверху вниз, от
   верхнего этажа. Тема строки и 3 бренда берутся из `retailInfo.floorsGuide`. Текст
   вида «детский этаж и белорусские дизайнеры: Familia, Mothercare | OVS kids, …; …»
   разбирается так: тема — часть до первого «:» без скобок, с заглавной буквы;
   бренды — первые 3 названия после двоеточия (делить по «,» и «;», убрать «и др.» и
   скобки, кавычки-ёлочки у названий вроде «Гиппо» оставить). Если в тексте нет
   двоеточия: тема — первая фраза до ~40 символов, бренды — из организаций Яндекса на
   этом этаже (топ-3 по reviewCount среди магазиноподобных). Если floorsGuide нет
   совсем, но у организаций есть этажи: тема — самая частая упрощённая категория этажа
   (исходную рубрику свести к простым словам: одежда, обувь, еда, дети, ювелирные,
   косметика, техника, спорт, дом и подарки, продукты, развлечения, услуги), две
   верхние через «и»; бренды — топ-3 по reviewCount. Этажи вроде 8 и 21 у Galleria —
   гостиница и офисная башня: при наличии floorsGuide на табло только его этажи; без
   floorsGuide отбросить этажи выше самого высокого этажа, где ≥5 организаций.
3. **«Только здесь»** (белая карточка справа от табло на десктопе, под ним на мобилке).
   Бренды, которые есть в этом ТЦ и нет ни в одном другом ТЦ со снимком арендаторов
   Яндекса. Считать при сборке в `scripts/generate-catalog-data.mjs`: он уже грузит все
   снимки арендаторов (набор `tenants`, около строки 249) и собирает данные по slug
   (около строки 298). Для каждого ТЦ (посмотреть, как там известен kind) найти
   уникальные имена (нормализация: нижний регистр, ё→е, выкинуть всё, кроме букв и
   цифр), только магазиноподобные: рубрика про магазины, одежду, обувь, ювелирное,
   косметику, электронику, рестораны, кафе, фастфуд, детское, спорт, развлечения.
   Выкинуть туалеты, банкоматы, банки и микрофинансы, криптоматы, офисы, гостиницы,
   казино, ломбарды, организацию мероприятий, перевозки, мусорные рубрики вида «этаж N»
   и имена короче 3 символов. Сортировка по reviewCount по убыванию, взять 7 штук
   {name, label}, где label — категория простыми словами («обувь», «ресторан»,
   «одежда»). Положить в данные здания, которые страница уже читает (найти, где
   собирается `tenants: tenantsBy.get(slug)` и как страница их получает через
   `src/lib/buildData.ts`; добавить поле вроде `uniqueBrands`). Заголовок карточки
   «Только здесь», подпись «Этих магазинов нет в других торговых центрах Минска из
   нашего каталога». Показывать только при ≥3 пунктах. Без данных сборки карточка
   просто не выводится, отдельного запроса в базу под неё НЕ делать. Логику
   уникальности вынести в чистую функцию и покрыть тестом на фикстуре.
4. **Подвал** приглушённым: «Источники: …» (оставить существующую строку источников
   floorsGuide) + «Полного списка арендаторов на странице нет: любой магазин находится
   поиском.» — только когда поиск показан.
