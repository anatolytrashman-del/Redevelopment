# Каталог «Коммерция в ЖК Минска» — план создания и наполнения (2026-10-06)

**Для сессии, которая получила этот файл.** Это самодостаточное задание:
решения приняты, владельца по ходу не переспрашивать, кроме мест, помеченных
**«спросить владельца»**. Иди по шагам сверху вниз: один шаг — одна сессия,
закончил шаг — отметь чекбокс и допиши строку в журнал в конце файла.
Перед каждым шагом — `git fetch origin && git status`, правила публикации и
ловушки — `CLAUDE.md` и `docs/claude/*`.

Исполнители: **Claude** — база, миграции, парсеры, страницы до ~50 строк,
мерж и деплой; **Codex** (`scripts/codex.sh -f docs/codex-tasks/<файл>.md`) —
крупная вёрстка от ~100 строк и фото; **субагенты** — массовый веб-ресёрч
(в основной контекст возвращать только таблицы).

## 1. Позиционирование

Раздел про **коммерческую** недвижимость в жилых комплексах: встроенные
торговые и офисные помещения первых этажей, машиноместа, кладовые,
бизнес-апартаменты. **Квартиры не показываем и не продаём** — ни в выдаче,
ни в карточке, ни в FAQ (кроме фона: «в ЖК N квартир, ~M жителей» как
характеристика аудитории для бизнеса).

Каталог — справочник по ЖК глазами бизнеса (тот же принцип, что у каталога
БЦ, `docs/bc-catalog-master-plan.md`): «что за аудитория, кто уже работает
на первых этажах, что продаёт застройщик, что есть на вторичке». Не
лотовый поисковик и не реклама наших объектов.

Образец по глубине — `/minsk/minsk-mir` (`src/pages/DistrictGuidePage.tsx`).
**Минск Мир заново не делаем**: в каталоге он есть строкой списка со ссылкой
на `/minsk/minsk-mir`, своей карточки `/minsk/zhk/minsk-mir` у него нет.

## 5. Структура раздела

Корень — **`/minsk/zhk`** (запрос «жк минск» — 3419/мес). Все страницы
кончаются FAQ по всему содержимому и дисклеймером с источниками
(`docs/claude/public-pages.md`).

| Адрес | Страница | Волна |
|---|---|---|
| `/minsk/zhk` | Каталог ЖК: список карточек, фильтры (район, застройщик, статус «строится/сдан», «есть лоты в продаже/аренде»), сводка цифр | 1 |
| `/minsk/zhk/:slug` | Карточка ЖК (блоки ниже) | 1 |
| `/minsk/zhk/district/:districtSlug` | ЖК района (только районы с ≥3 ЖК) | 2 |
| `/minsk/zhk/developer/:developerSlug` | Застройщик: его ЖК, что продаёт из коммерции, карточка компании | 2 |
| `/minsk/zhk/mashinomesta` | Машиноместа и паркинги в ЖК: от застройщика + вторичка, цены по ЖК | 2 |
| `/minsk/zhk/kladovye` | Кладовые в ЖК | 2 |
| `/minsk/zhk/biznes-apartamenty` | Бизнес-апартаменты: что это юридически, где продаются, цены | 2 |
| `/minsk/zhk/pod/magazin`, `/pod/kafe`, `/pod/uslugi` | Помещения в ЖК под вид бизнеса: лоты + аудитория + конкуренты по нише | 3 |
| `/minsk/zhk/area/:microdistrictSlug` | Микрорайон (Уручье, Лошица, Новая Боровая, Северный Берег) — только если там ≥2 ЖК | 3 |

**Карточка ЖК** (порядок блоков, по мотивам Минск Мира):

1. Шапка: фото, название, адрес, застройщик, статус, ссылка на сайт ЖК.
2. Ключевые цифры: домов, квартир (сдано/всего), оценка жителей
   (квартиры × 2,4 — формулу показать в дисклеймере), м² коммерции, лотов
   в продаже/аренде, медиана цены м² продажи и ставки аренды.
3. Застройщик — карточка по `docs/bc-developer-cards.md`.
4. Карта: дома ЖК, остановки/метро, ближайшие ТЦ и БЦ из наших каталогов.
5. **Что уже работает на первых этажах** — организации с Яндекс Карт
   по категориям (кафе, магазины, услуги): сводно по ЖК и по каждому дому
   (шаг 8а). Это блок под запросы «кафе/магазины <ЖК>».
6. Каких ниш не хватает — плотность бизнеса по нишам вокруг (как
   «Плотность бизнеса» у Минск Мира), без выдуманных выводов.
7. От застройщика: таблица лотов (тип, дом, этаж, м², терраса, цена,
   цена м²), отдельно машиноместа и кладовые сводкой.
8. Вторичка и аренда: объявления Kufar/Realt, привязанные к домам ЖК.
9. Очереди и сроки сдачи (хронология из СМИ/деклараций).
10. Транспорт и генераторы трафика.
11. Соседние ЖК.
12. FAQ → дисклеймер с источниками.

## 6. Модель данных

- ЖК — строка `business_centers` с `kind = 'zhk'` (slug, name, address,
  district, metro, photos, developer, координаты — как у БЦ).
- Специфика ЖК — новая колонка `zhk_info jsonb` (по аналогии с
  `retail_info` у ТЦ): `houses` (массив `{label, address, status,
  handoverYear, flats}`), `flatsTotal`, `commercialAreaM2`, `stages`,
  `developerSite`, `commercialUrl`, `sources` (массив ссылок), `facts`
  (массив `{text, source}`).
- Лоты застройщика — `primary_market_offers`, новая колонка `complex_slug`
  (FK по смыслу на `business_centers.slug`), `source` = домен застройщика.
  Старые строки bir.by Минск Мира — `complex_slug = 'minsk-mir'`.
- Вторичка — `citywide_offers` + новая колонка `zhk_slug` (заполняется
  матчингом адреса с `zhk_info.houses[].address`).
- Миграции только добавляют (правило совместимости), в конце
  `NOTIFY pgrst, 'reload schema';`.
