# Грабли и ключевые утилиты (полные разборы)

> Справочник вынесен из `CLAUDE.md` 2026-09-30, чтобы не грузить его в каждую сессию.
> Текст перенесён без изменений. Читать, когда задача касается темы файла.

## Ключевые паттерны/утилиты

- **PostgREST отдаёт максимум 1000 строк** (настройка `max_rows` проекта). Любая
  выборка, где строк может стать больше, — постранично через `.range()`, иначе
  хвост теряется МОЛЧА, без ошибки. Так из приложения пропадали 141 карточка
  поставщика и 393 снимка сайтов (разбор 2026-09-15).
- **`resend_message_id` — не заголовок `Message-ID` письма.** Первый выдаёт
  `POST /emails` (uuid), второй ставит Amazon SES, через который Resend
  отправляет (`<…@eu-west-1.amazonses.com>`), и именно на него ссылается
  `In-Reply-To` ответа поставщика. Настоящий заголовок отдаёт
  `GET /emails/{id}` в поле `message_id`; у нас он лежит в
  `message_id_header` и заполняется по событию `email.sent`
  (`api/_emailEvents.js`). Матчинг ответа по `resend_message_id` не работает
  и не заработает.
- **Подписка на вебхук ≠ его обработка.** Endpoint
  `api/purchase-email-webhook.js` был подписан в Resend на все типы событий с
  2026-08-29, но до 2026-09-16 читал только `email.received` — отлупы «такого
  ящика нет» полгода уходили в `{skipped:true}`. Список событий смотреть
  `GET https://api.resend.com/webhooks`, а не по тому, что endpoint
  зарегистрирован.
- **В ответе поставщика лежит НАШЕ же письмо.** Любой разбор ТЕКСТА
  входящего письма моделью (цены, условия, намерения) обязан сначала
  отрезать процитированную переписку — `stripQuotedReply` в
  `api/_emailText.js`. Иначе модель читает наш запрос с ведомостью как
  предложение поставщика и записывает наши собственные числа как его цены.
  Признаки резки выведены по 125 живым письмам, менять их — только с такой
  же проверкой по базе.
- **`\b` в JS-регулярках для кириллицы не работает.** Граница слова
  определена по ASCII, между «писали» и пробелом её нет — `/писали\b/`
  молча не находит ничего. Конец русского слова проверять lookahead'ом
  `(?![\p{L}])` с флагом `u`.
- **`create or replace function` с ДРУГИМ числом аргументов не заменяет
  функцию, а заводит вторую.** Дальше любой вызов со старым числом
  аргументов падает с «function is not unique» — то есть ломается всё, что
  звало функцию раньше. Добавляешь параметр — сначала `drop function` со
  старой сигнатурой, в той же миграции (так сделано с `auto_reply_apply`).
- **`revoke ... from anon, authenticated` НЕ закрывает функцию.** Postgres при
  создании функции выдаёт EXECUTE роли PUBLIC, а anon/authenticated его
  наследуют — отзыв у них персонально ничего не меняет, вызов через PostgREST
  по-прежнему проходит. Так полгода была открыта `auto_reply_apply`
  (SECURITY DEFINER, ставит письмо поставщику в очередь отправки), хотя в
  документации значилось «права отозваны». Закрывать всегда
  `revoke all on function … from public, anon, authenticated;` плюс явный
  `grant execute … to service_role;`.
- **`claude-sonnet-5` через ProxyAPI требует `thinking: {type: 'disabled'}`.**
  По умолчанию модель уходит в extended thinking и съедает им весь лимит
  вывода: ответ приходит с HTTP 200, `stop_reason: max_tokens` и ПУСТЫМ
  текстом, а разбор падает на «повреждённый JSON». Откат на другую модель по
  коду ответа при этом не срабатывает — формально это успех. Haiku
  (`claude-haiku-4-5-20251001`) этим не страдает.
- **Правила, общие для фронта и `api/*.js`, живут в ДВУХ файлах-близнецах.**
  Serverless-функции — голый JS и импортировать TypeScript из `src/` не
  умеют, поэтому такая логика дублируется (`src/data/vat.ts` ↔ `api/_vat.js`
  — НДС; регулярка определения ботов в `src/lib/botDetection.ts` ↔ инлайн-скрипт
  в `index.html` (счётчики стартуют до бандла; копии сверяет тест); `offerFollowupState` в `src/data/supplierResearch.ts` ↔
  `supabase/functions/process-followups` — пороги дожима). Правится одна
  сторона — правится и вторая: расхождение означает, что счёт, записанный
  автоматически, и тот же счёт, подтверждённый руками, дадут разные цены, а
  интерфейс покажет «пора напомнить» там, где воркер промолчит.
- **Разовый прогон по живой базе не требует service-role ключа** (его в
  окружении сессии нет). Читать и писать можно через Management API
  (`SUPABASE_ACCESS_TOKEN`, см. раздел «SQL-миграции»), а модель дёргать
  напрямую с `PROXYAPI_KEY`. Так сделан бэкфилл сопоставления позиций счетов
  2026-09-16 — владельцу не пришлось ничего запускать руками.

- **Фирменный красный и «опасно» в палитре — один и тот же цвет.**
  `--color-primary` (#e4152b) и `--color-danger` (#d21e34) различаются на
  глаз незаметно, а `Badge tone="primary"` и `tone="danger"` в списке
  читаются одинаково. Поэтому нейтральный статус («Заказано») нельзя красить
  в `primary`: он выглядит аварией рядом с «Отменён». Рабочая шкала для
  статусов — серое «движения нет», жёлтое «в работе», зелёное «довели до
  конца», красное «есть проблема» (см. `statusTone` в
  `components/suppliers/PurchaseOrdersTab.tsx`).
- **Вложенных модалок у нас нет и быть не может.** У `Modal` (components/ui)
  жёсткий `z-50` и СВОЙ обработчик Escape на каждую копию: вторая модалка
  поверх первой рисуется только по порядку в DOM, а Escape закрывает обе
  разом. Нужна «форма внутри карточки» — показывать её ВМЕСТО тела той же
  модалки, с кнопкой «Назад» (так сделана форма поставки в
  `components/suppliers/PurchaseDeliveries.tsx`).
- **Пустая строка из `<input type="date">` — это не дата.** В колонку `date`
  она уходит ошибкой `invalid input syntax for type date`, а не NULL'ом.
  В `*Api.ts` любое поле даты писать через `value || null` (см. `dateOrNull`
  в `purchaseOrdersApi.ts`) — иначе «очистил дату и сохранил» падает.
- **Всё, что делает попытку уникальной, считать ДО `withRetry`, а не внутри.**
  Повторяемая функция вызывается заново на каждой попытке, поэтому
  `const path = crypto.randomUUID()` внутри неё создаёт при повторе ВТОРОЙ
  объект в Storage, а не перезаписывает первый. Таймаут загрузки — 60 с, и
  тяжёлый файл в него не укладывается: `withTimeout` отдаёт ошибку, HTTP-запрос
  на сервере при этом доходит, повтор льёт копию. Так в `object-documents`
  накопилось 15 сиротских веб-архивов на 337 МБ (разбор 2026-09-20, исправлено
  во всех двенадцати загрузчиках: имя считается снаружи, у `.upload` стоит
  `upsert: true`).
- **Каталог БЦ живёт на `/minsk/bc` (с 2026-09-23, раньше `/minsk/bcminsk`).**
  Сегменты по-английски: `district`, `area`, `street`, `new`, `guide`,
  `rating/affordable|largest|class-b-plus|class-b-c`; названия — транслитом.
  Все старые адреса — 301 в `vercel.json`, одним прыжком; та же схема в
  `scripts/legacyCatalogUrls.mjs` переписывает ссылки в страницах,
  скопированных с прода. Меняешь адрес — правь оба места (сверяет
  `scripts/legacyCatalogUrls.test.js`).
- **Публичные страницы раздела БЦ читают данные из файлов сборки, не из
  базы (с 2026-09-23).** `scripts/generate-catalog-data.mjs` кладёт в
  `dist/data/` всё, что нужно разделу, а функции `*Api.ts` сначала смотрят
  туда (`src/lib/buildData.ts`) и идут в Supabase, только если файла нет;
  админка файлов не читает. Новый запрос со страницы раздела — добавить его
  набор в генератор, иначе он снова пойдёт в базу каждым посетителем. Пока
  REST закрыт, генератор берёт наборы из `scripts/catalog-data-fallback.json.gz`
  (снимает `scripts/snapshot-catalog-data-fallback.mjs` под ролью anon).
- **`withRetry` (`src/lib/withRetry.ts`)** — таймаут (15с, 60с для аплоадов) + один
  молчаливый повтор через 1с. Существует специально из-за Supabase free-tier
  "холодного старта": первый запрос после паузы иногда рвётся `TypeError: Load failed`
  (Safari) / `Failed to fetch` (Chrome) ещё до ответа сервера. Если пользователь снова
  сообщает про "Load failed" — **сначала проверь, не пропущена ли SQL-миграция**
  (см. схема-кэш выше), это частая настоящая причина, а не сам холодный старт.
- **`src/lib/glass.ts`** — общие классы для эффекта "жидкое стекло" (Apple Liquid
  Glass), единый вид админки и публичных страниц. Не re-имплементировать локально —
  импортировать `glassCardClass`/`glassCardShadow`/`glassPillClass`.
- **Растущие теги (AddableSelect)** — см. выше, паттерн для `requirement`,
  `contactMethod`, `clientType` и подобных "открытых" полей.
- **Кликабельные ссылки на диалог (`Leads.tsx`)** — `buildDialogLink(contactMethod, contact)`
  превращает Telegram-ник в `https://t.me/<handle>` (снимает `@`/`https://`/`t.me/`
  префиксы, валидирует по `/^[a-zA-Z][a-zA-Z0-9_]{4,31}$/`), для остальных методов
  связи линкует только то, что уже начинается с `http(s)://`.
- **`<img>` + оверлей во время смены данных** — если у компонента есть SVG/canvas
  оверлей поверх `<img src>` (see `BuildingPlanCanvas.tsx`), при смене исходных данных
  оверлей обновляется мгновенно, а `<img>` подтягивается по сети с задержкой — старый
  фон видно с новым оверлеем. Чинится через отдельный `displayedPlan`-стейт, который
  переключается только после фонового прелоада `new Image().onload`, не через прямой
  `plan.imageUrl` в JSX.
- **Числовые "нет данных" ловушки** — `!value` считает `0` отсутствием. Реальный баг
  этого класса: `zoneArea={selectedZone.area ?? 0}` для рабочих мест (площадь не
  задаётся) улетало на сервер как `0`, а `api/agreement-otp-request.js` проверял
  `!zoneArea` как "поле не заполнено" → блокировал подписание для всех рабочих мест.
  Исправлено (`isWorkstation` снимает требование). Держать в голове при любых
  будущих "пользователь всё заполнил, а форма ругается" репортах — сначала подозревать
  такую серверную валидацию, а не фронт.
