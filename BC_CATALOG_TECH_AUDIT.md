## 1. `/minsk/bcminsk` (каталог БЦ) — **статус: WIP, ты его ещё делаешь**

Логирую без давления на немедленное исправление — вернёмся вместе, когда сочтёшь каталог готовым.

- **H1 смешивает два разных кластера.** Кластеризация показала `catalog_core` («бизнес-центры минска», «бц минск») и `rent_core` («аренда офиса минск» и т.п.) как отдельные SERP-кластеры с 0% пересечения выдачи — то есть Яндекс/Google считают это разными интентами. Текущий H1 каталога («Бизнес-центры Минска: аналитика для аренды и покупки офиса») смешивает язык обоих кластеров в одном заголовке. Стоит решить: либо H1 чётко про каталог (`catalog_core`), а аренда/покупка — отдельная ссылка/блок, либо явно завести отдельную страницу под rent_core.
- **«Заполняемость» (occupancy/vacancy) — контент есть, но не на своём URL.** На странице уже есть блок «Что происходит на рынке офисов» (9.6% вакансия по городу, 11.3% по качественным БЦ, ссылки на Colliers / Результативную недвижимость) — по сути это готовый ответ на отдельный SERP-кластер про заполняемость/вакансию БЦ. Сейчас он зарыт внутри большой страницы каталога, а не живёт на URL, который соответствовал бы этому кластеру напрямую.
- **Нет фильтра «с парковкой».** Класс/район/микрорайон/метро/улица — фильтры уже реализованы правильно (это подтверждено). Единственная из ранее отмеченных «лёгких, низкоконкурентных» amenity-фильтров, которой не нашлось — «с парковкой».
- **Вес страницы.** Сырой HTML тяжёлый: сотни повторяющихся инлайн-SVG-иконок (`<svg class="lucide ...">`) на карточках, эффекты `backdrop-blur`/`box-shadow` по всей странице, ~45+ карточек БЦ до кнопки «показать ещё». `speedtest` показал `total_time` ≈10000 мс (при `connect_time` 356 мс — то есть сервер отвечает быстро, но что-то после этого долго). Это цифра самого Пиксель Тулс, ей не стоит доверять слепо — рекомендую перепроверить через pagespeed.web.dev, когда будет время.
- **Ложные срабатывания тулов — не баг сайта.** `fastaudit` показал `title:false`, `description:NotFound`, `h1s:false`, `text_symb_count:0` — при прямой проверке через `curl` страница отдаёт полноценные title/description/H1/текст/FAQ/источники. Это краулер самого Пиксель Тулс не смог распарсить тяжёлую страницу, а не реальная проблема сайта. `unikalnost` дал 0% (та же причина — не может забрать текст для сравнения). Игнорировать эти конкретные цифры из аудита для этой страницы.

## 5. Идеи новых страниц каталога БЦ (по кластеризации + SERP, этап 13)

Пауза на технических шагах (индексация/optimizationcheck) по твоей просьбе — сайт молодой, приоритет сейчас на архитектуре страниц, не на полировке. Ниже — конкретные идеи, каждая обоснована реальной кластеризацией (task #3) и составом топ-10 (task #4), а не догадкой.

**А. Быстрые фильтры внутри каталога (низкая конкуренция, свой SERP-кластер)**
- «с парковкой» — свой кластер в повторной кластеризации, подтверждено ранее как отсутствующий фильтр на сайте.
- «в центре города» / Центральный район — свой кластер («бизнес центры минск в центре города»), пересекается по доменам с «у метро» и «с парковкой» (2gis.by, realt.by, prometr.by, t-s.by — типичные каталожные конкуренты). Нужно проверить, есть ли уже фильтр по Центральному району — если да, отдельная страница не нужна, если нет — лёгкий довесок.
- «возле немиги» — свой кластер, при этом это НЕ административный район, а известный минчанам ориентир (метро/историческое место). Такие лендмарк-страницы («у вокзала», «у площади Победы» и т.п.) — отдельный паттерн от районных фильтров, стоит рассмотреть как микро-раздел «БЦ по ориентирам», если наберётся 3-5 таких кластеров.

**Б. Отдельные полноценные страницы (не фильтр, а свой контент/URL)**
- «Заполняемость / вакантность бизнес-центров Минска» — SERP этого кластера доминируют аналитика/бизнес-медиа (prometr.by, myfin.by, idc.by, probusiness.io, officelife.by, tochka.by) — совсем другой набор доменов, чем у «отзывов» или «лучших». Контент уже есть на сайте (блок «Что происходит на рынке офисов» внутри /minsk/bcminsk), но живёт не на своём URL. Кандидат на вынос в отдельную страницу с собственным title/H1 под этот кластер.
- «Отзывы о бизнес-центрах Минска» — НОВАЯ находка: кластеризация развела «рейтинг бизнес центров минска» (группа «...отзывы») и «лучшие бизнес центры минска» в РАЗНЫЕ кластеры. У «отзывов» в топ-10 — агрегаторы отзывов (zoon.by, otzyvy.by, firmi.by, tripadvisor.ru, mirstat.ru), у «лучших» — каталожно-рейтинговые сайты (bestbelarus.by, prometr.by, t-s.by, arendaofisa.by, domovita.by), где /minsk/bcminsk/reyting уже ранжируется на #2. То есть текущая страница рейтинга закрывает кластер «лучшие», но НЕ закрывает кластер «отзывы» — это разные интенты и разная выдача. Возможная новая страница: сбор отзывов арендаторов/резидентов о конкретных БЦ (UGC-формат), отдельно от аналитического рейтинга.

**В. Более крупная идея (отдельный раздел, не быстрый фикс)**
- Аренда офисов в бизнес-центрах — rent_core остаётся 0%-пересечения с catalog_core (подтверждено ранее). При этом внутри rent_core кластеризация уже даёт географические подкластеры: «аренда офиса минск мир» и «аренда офиса фрунзенский район минск» — оба отдельные группы. Это намекает, что если/когда будет отдельный раздел аренды (параллельно каталогу, а не смешанно как сейчас в H1 каталога), у него тоже могут понадобиться районные/локационные подстраницы — по аналогии с уже сделанной сегментацией каталога по районам, но под другим интентом.

Всё это — гипотезы по данным, не решения: часть уже может быть закрыта на сайте (особенно «в центре города» и «у метро» — не проверял, какие районы/станции у тебя заведены как фильтры). Скажи, что уже есть на сайте из этого списка — вычеркнем закрытое, а по остальному прикинем структуру URL для итогового ТЗ (задача #11).
