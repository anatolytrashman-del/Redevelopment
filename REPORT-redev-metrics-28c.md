## Откуда данные и как обновлять
Изучены `/workspace/lobsters-admin/gsc_collect.py`, SEO-сборщики `/workspace/gl-daily/collect.py`, `/workspace/pd/bing.py`; ключи найдены по именам в окружении и `card` файла `/home/box/sand-data/box-secrets.json`.

Выбран единый сбор на машине: `scripts/collect-search-metrics.py` → `data/search-metrics.json` → защищённый staff-сессией `GET /api/search-metrics`. Это простой воспроизводимый снимок без внешних ключей в Vercel; исходные секреты и рефереры посетителей в репозиторий не попадают.

GSC — сервисный аккаунт, только `webmasters.readonly`, Search Analytics `web/final`, запрошены 480 дней. Bing — `GetRankAndTrafficStats`. Vercel — официальный Web Analytics API, production, по дням с фильтром рефереров; окно 61 день (API ограничивает дневной запрос 62 днями). Старшая история сохраняется при повторном сборе, неудачный источник сохраняет предыдущий снимок со статусом `stale`; запись JSON атомарная.

Обновление на машине (Python с `google-api-python-client`, `google-auth`):
```bash
/workspace/gsc-venv/bin/python scripts/collect-search-metrics.py --secrets-file /home/box/sand-data/box-secrets.json
```
Либо передать сборщику `GSC_SERVICE_ACCOUNT_JSON` (JSON или путь), `BING_WEBMASTER_API_KEY`, `VERCEL_ANALYTICS_TOKEN` через env. Затем проверить и закоммитить обновлённый снимок. Текущая страница перечитывает опубликованный снимок, **автоматический суточный сбор/публикация не настроены**; новый снимок попадёт на сайт только с отдельно разрешённой выкладкой.

Сборщик поддерживает ИИ-рефереры + `utm_source=chatgpt.com` и другие ИИ-источники, но на текущем тарифе автоматически переходит на рефереры; UTM-only переходы без ИИ-реферера **не учтены**.
