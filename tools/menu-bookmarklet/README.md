# Закладка «Снять меню»

Читает разделы каталога поставщика прямо из отрисованной страницы.

Владелец, 2026-09-14: «протестируем твоё решение по DOM и без расширения,
закладкой. Если будет работать в 7 из 10 случаев, уже супер».

## Зачем

Серверный краулер (`supplier_site_snapshots`) качает голый HTML без
JavaScript и поэтому ломается тремя способами: видит пустоту там, где меню
рисует скрипт (77volt.ru, aviastal.ru — 0 разделов), уходит в сотни фильтров
одного раздела и не доходит до соседних вкладок (3dplitka.ru), или упирается
в капчу (169.ru). В браузере страница уже отрисована, и — главное —
подменю, которое показывается только при наведении, почти всегда УЖЕ лежит
в разметке, просто спрятано стилями. Один клик заменяет два десятка
наведений со скриншотами.

Расход при этом падает на порядок: разбор Авиасталь по 24 скринам стоил
169 тысяч токенов, то же дерево текстом — около 3.5 тысяч.

## Установка

```bash
node tools/menu-bookmarklet/build.mjs   # → install.html
```

Открыть `install.html`, перетащить кнопку на панель закладок.

## Как пользоваться

Открыть сайт поставщика (лучше сразу каталог) → нажать закладку → в окне
появится дерево разделов → «Скопировать» или «Скачать .txt».

Ничего никуда не отправляется: это проверочная версия. Транспорт (расширение
с боковой панелью, отправка прямо в базу, редактирование контактов) делаем
после того, как станет понятно, на скольких сайтах распознавание вообще
работает.

Дальше текст идёт обычным путём:

```bash
node scripts/supply-categories/review.mjs sections --host=… --file=…
node scripts/supply-categories/review.mjs next --hosts=…   # → diff → apply
```

## Что внутри

1. Ищет контейнеры навигации: `nav`, `[role=navigation]`, элементы с
   menu/nav/catalog в классе или id. Вложенные выкидывает, чтобы одни и те
   же ссылки не собрались дважды.
2. Берёт из них ссылки, отсеивая `#`, `javascript:`, `tel:`, `mailto:` и
   явно не-товарные пункты (контакты, доставка, корзина, вакансии…).
   Список исключений намеренно короткий: «Услуги» и «Производство» в него
   НЕ входят — у Авиасталь «Производство» оказалось настоящим товарным
   разделом.
3. Глубину считает по вложенности списков `<ul>`/`<ol>`. Меню на `<div>`
   выйдет плоским — это нормально, плоский список названий остаётся уликой.
4. Если в навигации нашлось меньше 8 ссылок — запасной путь: самая большая
   группа ссылок с общим началом пути (`/catalog/…`, `/produkty/…`).

Проверено на двух синтетических страницах (меню со спрятанным подменю и
меню без `nav` вообще) — оба пути отрабатывают.

## Чего закладка не умеет

- Скриншоты (для меню-картинок остаётся загрузка скринов в карточке
  верификации).
- Работать на сайтах со строгой политикой безопасности страницы — там
  браузер просто не выполнит код закладки. Насколько это частый случай,
  как раз и покажет проверка на десятке сайтов.
- Подменю, которое подгружается с сервера в момент наведения: в разметке
  его заранее нет. Лечится в расширении (само наведёт курсор и дочитает),
  в закладке — нет.

## Отправка в админку (с 2026-09-14, второй заход)

Владелец после первой проверки: «я не хочу вручную пересылать каждый раз.
Надо так: открылась вкладка, Светлана нажала кнопку снимка, система записала
в память и, если всё ок, показала уведомление. Светлана вернётся в карточку,
заполнит телефон, сохранит».

Теперь так и работает, причём без сервера-приёмника, всплывающих окон и
токенов внутри закладки. Приём устроен на том, что вкладку с сайтом
поставщика открывает САМА админка (`openSupplierSiteTab` в
`SupplierVerificationTab.tsx`) — значит у этой вкладки есть ссылка на
открывшую её вкладку админки, и закладка отправляет дерево прямо туда
(`postMessage`). Админка авторизована живой сессией Светланы и пишет строку
в `supplier_menu_captures` сама.

```
карточка верификации → «Начать верификацию» открывает сайт вкладкой
      ↓  Светлана жмёт закладку «Снять меню»
дерево уходит в соседнюю вкладку админки → строка в supplier_menu_captures
      ↓  на сайте всплывает «Меню снято: 150 разделов»
Светлана возвращается в карточку, заполняет контакты, жмёт «Дальше →»
```

Поставщик при этом уходит из активной очереди в блок «ждут распознавания» —
его категории вот-вот изменятся разбором.

Запасной путь никуда не делся: если сайт открыт сам по себе (не из карточки)
или админка не ответила за 2.5 секунды, показывается прежнее окно с
копированием.

Доверять источнику сообщения нельзя — оно приходит с чужого домена, поэтому
админка проверяет ФОРМУ данных (своя метка, строковый хост, непустое дерево).
Худшее, что может сделать посторонняя страница, — записать строку-заготовку в
отдельную таблицу, которую всё равно смотрят глазами перед тем, как пустить
разделы в улики.

## Разбор снятого (на стороне сессии)

```bash
node scripts/supply-categories/captures.mjs list                    # что снято
node scripts/supply-categories/captures.mjs show --host=…           # глазами
node scripts/supply-categories/captures.mjs apply --host=… \
  --drop-after='Услуги'                                             # → manual:// разделы
node scripts/supply-categories/review.mjs next --hosts=…            # → diff → apply
```

Распознавать нечего — дерево уже текстом, субагент не нужен, расход близок к
нулю. Но просмотреть глазами НАДО: у msk.avangardrf.ru товарная часть вышла
идеальной (91 строка), а в хвосте оказались «Все акции», «Все новости» и
названия отдельных товаров — для этого и `--drop-after`.
