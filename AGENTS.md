# AGENTS.md — правила для Codex (OpenAI) в этом репозитории

Этот файл читает Codex (облачный и CLI). Полный свод правил проекта — `CLAUDE.md`,
он остаётся источником истины; здесь выжимка плюс то, что касается ТОЛЬКО Codex.
Разделение труда между Codex и Claude — `docs/codex-handoff.md`.

## Проект

CRM + продающий сайт для редевелопмента коммерческой недвижимости (домен
`redevelopment.pro`). React 19 + TypeScript + Vite 8 + Tailwind v4 + react-router-dom v7,
Supabase как база (на фронте только anon-ключ, доступ режет RLS), `api/*.js` — Vercel
serverless на голом JS (не TypeScript). Админка за `PasswordGate` под `/admin/*`,
публичные страницы — `/:slug` и `/plan/:token`.

Владелец русскоязычный: отвечать и писать описания PR по-русски. Код, комментарии в
коде и сообщения коммитов — как в существующем коде.

## Ветки и PR

- **Базовая ветка — `claude/redevelopment-platform-prototype-oodobu`, НЕ `main`.**
  Именно её собирает Vercel в прод. Отбранчовываться от неё и PR открывать в неё.
- Свою работу вести в отдельной ветке, имя произвольное, префикс `codex/`.
- **PR не мержить самостоятельно.** Мержит Claude или владелец после проверки.
- `git add` — только изменённые файлы поимённо, никогда `git add -A` / `git add .`.

## Сборка и проверки перед PR

```bash
npm ci          # если node_modules нет
npm run build:app   # tsc -b + vite build + генераторы; ~10 секунд
```

- **Никогда не запускать `npm run build`.** Он доходит до `scripts/prerender.mjs`,
  который локально всегда идёт в полном режиме: ~285 путей по отдельному headless-браузеру,
  двадцать минут. Нужен именно он — `PRERENDER_SKIP=1 npm run build`.
- `npm run lint` (oxlint) и `npm test` (vitest) — дёшевы, гонять можно.
- PR без чистого `npm run build:app` не открывать.

## Чего у Codex НЕТ и что он не делает

У песочницы Codex нет секретов проекта (`SUPABASE_SERVICE_ROLE_KEY`,
`SUPABASE_ACCESS_TOKEN`, `RESEND_API_KEY`, `VERCEL_TOKEN`, Google OAuth) и, как правило,
нет сети. Поэтому Codex **не**:

- применяет SQL-миграции в живую базу (`api.supabase.com`) — вместо этого кладёт готовый
  файл в `supabase/migrations/YYYYMMDD-<тема>.sql` и упоминает его в описании PR;
  применит его Claude через Management API;
- не ходит в Resend, Vercel, Google API, Telegram;
- не трогает прод-деплой и не мержит;
- не читает и не печатает секреты, не коммитит `.env`.

- не трогает `.github/workflows/` и настройки деплоя. Connector просит право записи в
  workflows пакетом, отказаться от него в GitHub нельзя, но пользоваться им не нужно:
  там лежат почасовые синки статистики и ручные запуски очередей, сломать их тихо
  легко, а заметить — нечем. Нужна правка воркфлоу — опиши её в описании PR словами,
  файл не меняй.

**Любая DDL-миграция заканчивается строкой `NOTIFY pgrst, 'reload schema';`** — иначе
PostgREST не видит новую колонку и фронт падает с `Could not find the 'x' column`.

Миграция должна быть совместима со старым кодом (её применят до того, как код доедет
до прода): добавлять — можно; переименовывать, удалять, ужесточать RLS — отдельным
шагом после релиза.

## Паттерн работы с данными

На каждую сущность одинаковая связка трёх файлов, эталон — `src/data/leads.ts` +
`src/lib/leadsApi.ts`:

1. `src/data/foo.ts` — `interface Foo` (camelCase, им оперирует приложение) и
   `interface FooRow` (snake_case, ровно колонки таблицы). Плюс открытые
   списки-константы для растущих enum-полей.
2. `src/lib/fooApi.ts` — `fromRow(row: FooRow): Foo`, `fetchFoo/insertFoo/updateFoo/
   deleteFoo`, все запросы через `withRetry`. `insert`/`update` принимают
   `Omit<Foo, 'id' | 'createdAt'>`.
3. Страница держит форму в стейте и мапит в обе стороны.

## Грабли, на которые здесь уже наступали

- **PostgREST отдаёт максимум 1000 строк.** Любая выборка, где строк может стать больше,
  идёт постранично через `.range()` — иначе хвост теряется МОЛЧА, без ошибки.
- **Пустая строка из `<input type="date">` — не дата.** В колонку `date` она уходит
  ошибкой `invalid input syntax for type date`, а не NULL. Писать через `value || null`
  (см. `dateOrNull` в `src/lib/purchaseOrdersApi.ts`).
- **`!value` считает `0` отсутствием данных.** Реальный баг этого класса блокировал
  подписание для всех рабочих мест (площадь `0` читалась как «поле не заполнено»).
- **Вложенных модалок нет и быть не может.** У `Modal` жёсткий `z-50` и свой обработчик
  Escape на каждую копию — вторая модалка поверх первой ловит Escape вместе с первой.
  Нужна «форма внутри карточки» — показывать её ВМЕСТО тела той же модалки, с кнопкой
  «Назад» (образец — `src/components/suppliers/PurchaseDeliveries.tsx`).
- **Фирменный красный и «опасно» — почти один цвет.** `--color-primary` (#e4152b) и
  `--color-danger` (#d21e34) неразличимы на глаз, поэтому нейтральный статус нельзя
  красить в `primary`. Шкала статусов: серое «движения нет», жёлтое «в работе»,
  зелёное «довели до конца», красное «есть проблема» (`statusTone` в
  `src/components/suppliers/PurchaseOrdersTab.tsx`).
- **`\b` в JS-регулярках для кириллицы не работает** — граница слова определена по ASCII.
  Конец русского слова проверять lookahead'ом `(?![\p{L}])` с флагом `u`.
- **`create or replace function` с ДРУГИМ числом аргументов заводит вторую функцию**,
  и дальше вызовы падают с «function is not unique». Добавляешь параметр — сначала
  `drop function` со старой сигнатурой, в той же миграции.
- **`revoke ... from anon, authenticated` не закрывает функцию** — EXECUTE наследуется
  от PUBLIC. Закрывать всегда `revoke all on function … from public, anon, authenticated;`
  плюс явный `grant execute … to service_role;`.
- **`<img>` + SVG/canvas-оверлей при смене данных** рассинхронизируются: оверлей
  обновляется мгновенно, картинка подтягивается по сети — видно старый фон с новым
  оверлеем. Лечится отдельным `displayed*`-стейтом после прелоада `new Image().onload`
  (см. `BuildingPlanCanvas.tsx`).

## Файлы-близнецы: правишь одну сторону — правь вторую

`api/*.js` — голый JS и импортировать TypeScript из `src/` не умеет, поэтому общая
логика продублирована. Расхождение означает, что счёт, записанный автоматически, и тот
же счёт, подтверждённый руками, дадут разные цены:

- НДС: `src/data/vat.ts` ↔ `api/_vat.js`
- пороги дожима поставщиков: `offerFollowupState` в `src/data/supplierResearch.ts` ↔
  `supabase/functions/process-followups`
- захват задания массовой рассылки: воркер в `supabase/functions/process-bulk-send-jobs`
  ↔ одноимённый скрипт в `scripts/` (порядок «захват → проверка → отправка» правится
  сразу в обоих — иначе поставщики получают по два письма)

## Общие утилиты — не переизобретать

- `src/lib/withRetry.ts` — таймаут (15с; 60с для аплоадов) + один молчаливый повтор.
  Оборачивать им все запросы в Supabase.
- `src/lib/glass.ts` — классы эффекта «жидкое стекло»: `glassCardClass`,
  `glassCardShadow`, `glassPillClass`. Локально не реимплементировать.
- `src/components/ui` — Button, Card, Badge, Input, Select, AddableSelect, ToggleGroup,
  Modal, TreeTable, SearchInput. Растущие enum-поля — через `AddableSelect` плюс
  `useMemo`, объединяющий пресет с фактически встречающимися значениями
  (образцы в `Leads.tsx`, `ObjectFormModal.tsx`).
